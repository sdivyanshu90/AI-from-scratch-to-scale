# Synthetic Data Generation and Knowledge Distillation

The quality and quantity of training data constrains every learned model.
Synthetic data generation creates training examples programmatically or via
a teacher model, bypassing the bottleneck of expensive human annotation.
Knowledge distillation transfers capabilities from a large, expensive
"teacher" model to a small, efficient "student" model by training on soft
probability distributions rather than hard labels. Together, these techniques
enable high-capability small models and reduce the cost of training at scale.

## 1. The Core Intuition (The "Why")

Hinton et al. (2015) introduced knowledge distillation with a striking
observation: a student trained on the teacher's probability outputs
(soft targets) learns much more efficiently than one trained on hard
one-hot labels. Why? The teacher's distribution over incorrect classes
contains information about relationships between classes — a "2" is more
likely to be confused with a "3" than a "7", which encodes meaningful
structure that hard labels discard.

For language models, Taori et al. (2023) demonstrated with Alpaca that
52,000 instruction-following examples generated by GPT-3.5 could fine-tune
a LLaMA-7B model to match GPT-3.5's instruction-following ability at a
fraction of the cost. Gunasekar et al. (2023) showed with phi-1 that a
1.3B model trained on high-quality "textbook" synthetic data outperformed
much larger models trained on raw internet data.

The key insight across both strands: **data quality dominates data quantity**
for fine-tuning and distillation. A small amount of expert-generated or
carefully filtered synthetic data can outperform terabytes of noisy data.

## 2. The Theoretical Underpinning

### Knowledge Distillation: Soft Targets

Hinton et al. (2015) train the student with a combination of the hard
label loss and a **distillation loss** against the teacher's output:

$$\mathcal{L} = (1 - \lambda) \mathcal{L}_\text{CE}(y, p_s) + \lambda \mathcal{L}_\text{KL}(p_t^T, p_s^T)$$

where:
- $p_s = \text{softmax}(z_s)$: student probabilities
- $p_t^T = \text{softmax}(z_t / T)$: teacher soft targets at temperature $T$
- $T$: temperature ($T > 1$ softens the distribution, revealing more structure)
- $\lambda$: interpolation coefficient

The **temperature scaling** in the teacher outputs:

$$p_i^T = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}$$

For large $T$, all classes receive non-negligible probability, revealing
the teacher's uncertainty structure. For $T \to \infty$, the distribution
approaches uniform. For $T = 1$, we recover the standard softmax.

The student must also use the same temperature $T$ during distillation
(and $T=1$ at inference time).

### Constitutional AI: Self-Improvement via Critique

Bai et al. (2022) introduced Constitutional AI (CAI): a model self-improves
its outputs by critiquing them against a set of principles (a "constitution")
and then revising them:

1. Generate an initial response $y_0$
2. Critique: "Identify ways $y_0$ could be harmful or dishonest..."
3. Revision: "Rewrite $y_0$ to address the critique..."
4. Repeat $K$ times to get $y_K$
5. Use $(x, y_K)$ as SFT training data

This is a form of synthetic data generation where the model's own reasoning
provides the annotation signal.

### Self-Play and Iterative Self-Improvement

A model can generate synthetic data by playing against itself:
- Generate a question, answer it, critique the answer, improve it
- For code: generate a problem, solve it, run tests, fix failures
- For math: generate a proof attempt, verify it symbolically, use correct steps as training data

**Rejection sampling fine-tuning (RFT)**: generate $N$ solutions per
problem, keep only correct ones (verified by a ground-truth checker or
PRM), fine-tune on the filtered set. Yuan et al. (2023) showed this
iteratively improves mathematical reasoning.

### Knowledge Distillation for Sequence Models

For autoregressive LMs, the distillation loss is computed token by token:

$$\mathcal{L}_\text{seq-KD} = -\sum_{t=1}^{T} \sum_{v=1}^{V} p_t^T(v) \log q_t(v)$$

where $p_t^T$ is the teacher's softmax at position $t$ (temperature $T$)
and $q_t$ is the student's probability. This is the forward KL divergence,
which is mode-covering: the student is penalised for not covering all
modes the teacher covers.

## 3. Implementation: From Scratch (Python + PyTorch)

```python
from __future__ import annotations

import torch
import torch.nn as nn
import torch.nn.functional as F


class DistillationLoss(nn.Module):
    """Combined cross-entropy + KL distillation loss.

    Combines the supervised hard-label loss with the distillation loss
    against the teacher's soft targets. The temperature T controls
    how much of the teacher's uncertainty structure is transferred.
    """

    def __init__(
        self,
        temperature: float = 4.0,
        alpha:       float = 0.7,
    ) -> None:
        super().__init__()
        self.T     = temperature
        self.alpha = alpha    # Weight for distillation loss

    def forward(
        self,
        student_logits: torch.Tensor,
        teacher_logits: torch.Tensor,
        labels:         torch.Tensor,
    ) -> torch.Tensor:
        """Compute distillation + hard-label loss.

        Args:
            student_logits: (batch, num_classes) student outputs.
            teacher_logits: (batch, num_classes) teacher outputs (no gradient).
            labels:         (batch,) hard ground-truth labels.

        Returns:
            Scalar combined loss.
        """
        # Hard-label cross-entropy
        hard_loss = F.cross_entropy(student_logits, labels)

        # Soft targets: apply temperature to both teacher and student
        soft_teacher = F.softmax(teacher_logits / self.T, dim=-1)
        soft_student = F.log_softmax(student_logits / self.T, dim=-1)

        # KL divergence: D_KL(teacher || student)
        # Multiply by T^2 to rescale gradients (Hinton et al., 2015)
        kl_loss = F.kl_div(soft_student, soft_teacher, reduction="batchmean") * (self.T ** 2)

        return (1 - self.alpha) * hard_loss + self.alpha * kl_loss


def generate_synthetic_instructions(
    seed_tasks:  list[str],
    llm_call:    callable,
    n_per_seed:  int = 5,
) -> list[dict[str, str]]:
    """Generate synthetic instruction-following data via self-instruct.

    Given seed tasks, ask the LLM to generate similar but diverse tasks
    and their corresponding outputs. This is the approach used by Alpaca.

    Args:
        seed_tasks:  Small set of example (instruction, output) pairs.
        llm_call:    Function(prompt) -> str.
        n_per_seed:  Number of new tasks to generate per seed task.

    Returns:
        List of {"instruction": ..., "output": ...} dicts.
    """
    seed_examples = "\n".join(
        f"Instruction: {t['instruction']}\nOutput: {t['output']}"
        for t in seed_tasks[:5]
    )
    prompt = (
        f"Below are some example instruction-output pairs:\n\n{seed_examples}\n\n"
        f"Generate {n_per_seed} new diverse instruction-output pairs "
        "on different topics. Format each as:\n"
        "Instruction: ...\nOutput: ...\n"
    )
    raw    = llm_call(prompt)
    pairs  = []
    blocks = raw.strip().split("\n\n")
    for block in blocks:
        lines = block.strip().split("\n")
        inst  = next((l.replace("Instruction:", "").strip() for l in lines if l.startswith("Instruction:")), None)
        out   = next((l.replace("Output:", "").strip() for l in lines if l.startswith("Output:")), None)
        if inst and out:
            pairs.append({"instruction": inst, "output": out})
    return pairs
```

## 4. Implementation: Production-Grade

```python
from __future__ import annotations

import json
from pathlib import Path

from openai import OpenAI


def self_instruct_pipeline(
    seed_file:  str,
    output_file: str,
    n_rounds:   int = 10,
    batch_size: int = 20,
    model:      str = "gpt-4o-mini",
) -> None:
    """Generate a synthetic instruction-following dataset using Self-Instruct.

    Each round, sample 6 random seed tasks, ask the model to generate
    batch_size new tasks, filter out duplicates, and add to the pool.

    This mirrors the Alpaca data generation pipeline.

    Args:
        seed_file:   JSONL file with initial {"instruction", "output"} examples.
        output_file: JSONL file to write generated examples to.
        n_rounds:    Number of generation rounds.
        batch_size:  New tasks per round.
        model:       OpenAI model for generation.
    """
    import random
    client   = OpenAI()
    seed_data = [json.loads(l) for l in Path(seed_file).read_text().splitlines()]
    generated = list(seed_data)

    for _ in range(n_rounds):
        # Sample 6 examples as context
        sample  = random.sample(generated[-200:], min(6, len(generated)))
        context = "\n\n".join(
            f"Instruction: {ex['instruction']}\nOutput: {ex['output']}"
            for ex in sample
        )
        prompt  = (
            f"Here are some instruction-output pairs:\n\n{context}\n\n"
            f"Generate {batch_size} diverse, high-quality instruction-output pairs "
            "on different topics. Each must be clearly useful for instruction-following "
            "training. Format:\n"
            "Instruction: <instruction>\nOutput: <output>\n"
        )
        response = client.chat.completions.create(
            model    = model,
            messages = [{"role": "user", "content": prompt}],
        )
        raw    = response.choices[0].message.content or ""
        blocks = raw.strip().split("\n\n")
        with open(output_file, "a") as f:
            for block in blocks:
                lines = block.strip().split("\n")
                inst  = next((l.replace("Instruction:", "").strip() for l in lines if l.startswith("Instruction:")), None)
                out   = next((l.replace("Output:", "").strip() for l in lines if l.startswith("Output:")), None)
                if inst and out and len(inst) > 10:
                    entry = {"instruction": inst, "output": out}
                    generated.append(entry)
                    f.write(json.dumps(entry) + "\n")


def filter_by_quality(
    dataset:     list[dict],
    llm_judge:   callable,
    min_score:   float = 0.7,
) -> list[dict]:
    """Use an LLM judge to score and filter synthetic data by quality.

    LLM-as-judge is used in production pipelines (MT-Bench, AlpacaEval)
    to filter out low-quality or unsafe generated examples.

    Args:
        dataset:   List of {"instruction", "output"} dicts.
        llm_judge: Function(instruction, output) -> float score in [0, 1].
        min_score: Minimum quality score to keep an example.

    Returns:
        Filtered dataset.
    """
    return [
        ex for ex in dataset
        if llm_judge(ex["instruction"], ex["output"]) >= min_score
    ]
```

## 5. Production Pitfalls & Pro-Tips

- **Mistake:** Using the same model to generate and evaluate synthetic data.
  The model's biases and errors propagate into the training data, creating
  a feedback loop that reinforces mistakes.

  **Fix:** Use a stronger model to generate data and a different (or
  ground-truth) evaluator for quality filtering. For math, use a symbolic
  verifier; for code, use unit tests.

- **Mistake:** Generating synthetic data without checking for contamination
  with the test set. If the teacher's training data overlaps with your
  evaluation benchmark, your results will be inflated.

  **Fix:** Decontaminate synthetic data using n-gram overlap or embedding
  similarity against your evaluation benchmarks before training.

- **Mistake:** Setting temperature $T = 1$ in knowledge distillation (no
  temperature scaling). At $T=1$, the teacher's distribution is sharp and
  contains little more information than the hard labels.

  **Fix:** Use $T = 3$–$6$ for distillation. Validate by measuring
  entropy of the teacher's soft targets; it should be meaningfully higher
  than the student's.

- **Mistake:** Training a distilled model only on the teacher's outputs
  and ignoring the original ground-truth labels ($\lambda = 1$). When the
  teacher makes mistakes, the student learns them.

  **Fix:** Use the combined loss ($\lambda = 0.7$ is a common default).
  Always include the hard-label term.

- **Mistake:** Treating synthetic data as a direct replacement for
  human-curated data for safety-critical tasks. LLMs can generate
  syntactically plausible but factually wrong or biased training examples.

  **Fix:** Human-review a random sample of synthetic data before using it
  in production training runs. Track the error rate of your generation
  pipeline.
